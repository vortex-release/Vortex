# Kill sound and input binding (3.9)

**Settings > Kill sound:** enable the feature, choose a local sound with Browse (or paste its path), and set Volume. An empty path uses the included short tone. Test sound previews the selection even while the kill trigger is disabled; it also reloads a file edited at the same path. WAV and MP3 use Windows Media Foundation. Other formats in the picker depend on the installed Windows decoders. Clips must be mono/stereo, at most 10 seconds and 64 MB. Invalid files show a short error and never silently play a different sound. The feature starts disabled for existing profiles.

The selected file stays in its original location. `[Visual] killSoundEnabled`, `killSoundVolume` and the UTF-8 `KillSoundHex` path save through the existing atomic profile writer. Auto save, Save, Load and Reset apply normally. Decoding, file selection and playback run off Present. PCM is cached, XAudio2 provides independent volume, and up to eight voices allow closely spaced kills to overlap. Voices are destroyed before their audio buffers, and shutdown closes the picker and joins the worker.

The CS2 reader samples only the local controller's `m_pActionTrackingServices` and `m_iNumRoundKills`. Both fields are imported from the existing JSON/HPP snapshot in Updated Offsets, bringing the consumed global/schema count to 39. Identity, complete controller handle, service pointer and counter bounds are checked. The initial sample establishes a baseline. Round resets, disable/enable, missing data, a new controller or service, and implausible score corrections do not replay old kills. No remote player's death or spectator target is used as the trigger. This polls the replicated counter on eligible Presents; it is not a server event listener.

**Tracking > Bind > Set bind:** the label changes to **Waiting for input...**, and the next new keyboard key, mouse button or wheel direction becomes the bind. The initiating click, already-held buttons, repeats and mouse motion are ignored. Left/right modifiers are distinguished. Escape can be bound too. Switching focus cancels an unfinished capture. Keyboard and mouse buttons use hold behavior; wheel movement gives a 120 ms follow pulse. Captured input is consumed before menu shortcuts and text fields.

If Insert is assigned to follow, Ctrl+Insert opens/closes the menu. If the drawing-toggle key (normally Home) is assigned, Ctrl plus that key toggles drawing. The menu displays the changed shortcut. This preserves access without excluding those keys from binding. Operating-system shortcuts that prevent delivery to the game cannot be captured. `TrackingConfiguration` retains its ABI: virtual keys occupy 1–255, with 256–259 representing wheel up/down/left/right. Hosts providing CameraInput still supply their own activation state; the normal demo handles these wheel values too.

Verification covers local counter changes and identity failures, capture ordering, modifier distinction, repeat suppression, focus loss, shortcut collisions, wheel activation, Unicode path/settings validation, exact WAV decoding, invalid/oversized audio, cancellation and a muted real XAudio2 output graph. The DLL smoke clicks the actual sound controls and Set bind button, captures a keyboard key and mouse side button, and verifies Save/Load. A live CS2 kill-trigger test was not performed for this release.

Implementation references: Microsoft's [PCM decoding workflow](https://learn.microsoft.com/en-us/windows/win32/medfound/tutorial--decoding-audio), [XAudio2 buffer lifetime](https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/nf-xaudio2-ixaudio2sourcevoice-submitsourcebuffer) and [voice sample counters](https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/ns-xaudio2-xaudio2_voice_state).
