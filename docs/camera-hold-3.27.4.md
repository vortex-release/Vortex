# Third-person hold key, 3.27.4

In Assists > Camera, enable Third-person camera and set Camera activation to Hold key. Middle Mouse is the initial binding; Set camera key captures a keyboard key or mouse button. Releasing it returns to the engine's first-person camera on the next active view setup after the input snapshot updates. No persistent camera-origin patch or toggle latch is used.

Vortex already had the camera offset and collision-sweep implementation. The supplied Anthony source showed the missing activation gate. This update connects an independent hold binding to Vortex's existing verified view setup and wall-clipped camera arm; it does not copy the reference's unguarded origin writes.

Profiles store cameraVisuals.thirdPersonMode (0 Always, 1 Hold key) and cameraVisuals.thirdPersonKey (Windows button/key code). Missing fields default to Always and Middle Mouse, preserving older enabled profiles. Keyboard and mouse buttons are valid; wheel pulses and unbound/unknown mode values are rejected. Camera capture uses its own target so it cannot overwrite camera-tracking bindings.

Hold state comes from WindowBridge's physical-input snapshot, which ignores Vortex-generated input. This prevents a synthetic Jumper Space-up from releasing a physically held Space camera binding. Menu/chat pause and foreground state gate Hold mode; the existing scope preference and alive/build/trace validation still apply. The camera remains a per-view output, so inactive/disabled states use the origin regenerated by the game.

Offline coverage includes hold/release, master disable, scope behavior, focus/chat pause, synthetic-input independence, configuration round trips, older-profile defaults, and actual menu capture/persistence without changing tracking. The focused preflight is recorded in release/verification-3.27.4.json.
